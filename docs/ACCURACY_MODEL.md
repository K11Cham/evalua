# What the local model adds

Generated by `npm run eval:model` on 2026-11-16, with Ollama on a Ryzen 7 9700X / RTX 5060. Fictitious records only; temperature 0, one run per model.

evalua reads and evaluates a transcript without any model. The optional local model (Settings → language model on this computer) does one thing: it suggests English names for courses the built-in dictionaries cannot translate. It does not read the document, and it does not change grades, credits, grade levels or the US subject, because subject matching uses the name as printed. Every other number in [ACCURACY.md](ACCURACY.md) is the same with or without it.

## Short answer

- **On the golden set it barely matters.** The dictionaries already translate almost every course name, so only 4 real course names (all damaged by OCR) were left for the model. “English name close to the reference” goes from 96.1% to 96.3% (qwen2.5-coder:7b) and 96.3% (qwen2.5-coder:14b).
- **Where the dictionaries have no entry, the model is the only source of an English name.** Asked to translate every non-English course name on its own (part 2), qwen2.5-coder:7b names the right subject for 235/276 (85%), and qwen2.5-coder:14b names the right subject for 246/276 (89%), against 274/276 (99%) for evalua's rules. It is a fallback, not a replacement.
- **Model choice:** on the damaged names the button actually sends (part 1), qwen2.5-coder:7b named the most subjects correctly; across every name (part 2), qwen2.5-coder:14b did. qwen2.5-coder:7b was 6× faster than qwen2.5-coder:14b. Either way the answers appear as suggestions a counselor can change, and the change log records the model that gave them.
- **The model's mistakes are confident.** It turns “Matemáticas IV” into “Calculus I” rather than saying it is not sure. That is why evalua uses its answer only for the English name, never for the subject or credit.
